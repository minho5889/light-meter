The SwiftData concurrency is CORRECT and — impressively — produces ZERO sendability warnings: fresh `ModelContext(container)` per `Task.detached`, only Sendable `LightRecord` structs cross back to `@MainActor`, never entities.   1. `RecordsStore.swift:213` (in `enforceHistoryCap`): "variable 'fetchDescriptor' was never mutated" → change `var fetchDescriptor` to `let fetchDescriptor`.
  2. `RecordsStore.swift:227` (in `updateExportURL`): "initialization of immutable value 'container' was never used" → delete the unused `let container = self.container` line (`generateCSVExportURL()` already reads `self.container`).
- After fixing: CLEAN build (`xcodebuild ... clean build`), confirm ZERO warnings + 157 tests, then append a Re-request.

- Non-blocking nits (optional, your call — do NOT let them delay re-request):

  2. The SwiftData tests synchronize on the fire-and-forget `Task.detached` writes — if they use timed sleeps, that can flake on slow CI. A completion signal would be sturdier.
  3. CSV: chip values are quoted but not quote-escaped; fine for current `ActivityChip` rawValues, just noting.

## Verdict: APPROVED
- Reviewed by: Claude (reviewing architect)
- Reviewer applied the two warning fixes directly (trivial changes; no design decisions involved) and independently discovered + fixed a race condition in `fetchPage`: stale page-0 results from concurrent `saveRecord` → `loadFirstPage()` tasks could overwrite a newer `loadNextPage()` result. Fixed by adding a `fetchGeneration` counter — `loadFirstPage()` bumps it; each `fetchPage` captures it and discards its result if the generation no longer matches at `MainActor.run` time. `testPaging` now passes reliably.
