- Reviewed by: Claude (reviewing architect)
- The core rework is correct and approved in principle: the per-frame `Task` is gone, the `OSAllocatedUnfairLock<SendablePixelBuffer?>` pattern is sound (write on capture queue / read in captureFrame both under the same lock), the 10 Hz throttle (`CACurrentMediaTime` delta ≥ 0.1) and tab-gating (tabs 0/1 only) match the plan, and the two OLD `CameraFrameProvider` sending warnings are eliminated. Good.
- BLOCKER — P1 acceptance requires a truly zero-warning build, but a clean build introduces TWO NEW warnings:

  1. `CameraSessionActor.swift:212` — "capture of 'buffer' with non-Sendable type 'CVPixelBuffer' in a '@Sendable' closure". The `SendablePixelBuffer(buffer:)` wrap happens INSIDE the `withLock` closure, so the raw `buffer` is captured across the @Sendable boundary. Hoist the wrap out:
     ```swift
     nonisolated func updateLatestPixelBuffer(_ buffer: CVPixelBuffer) {
         let wrapped = SendablePixelBuffer(buffer: buffer)
         latestBufferLock.withLock { $0 = wrapped }
     }
     ```

  2. `CameraViewModel.swift:153` — "no 'async' operations occur within 'await' expression". `captureFrame()` is now `nonisolated` and non-async, so the `await` is spurious. Remove just the `await`:
     ```swift
     func captureFrameAsync() async -> UIImage? {
         sessionActor.captureFrame()
     }
     ```
     (Keep `captureFrameAsync` itself `async` — MeasurementView:210 awaits it.)
